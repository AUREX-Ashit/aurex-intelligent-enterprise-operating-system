# Historical UI Concepts

## Purpose

These HTML designs were created before the current AUREX Enterprise
Architecture and Enterprise Experience Foundation.

They are retained as Historical Design Assets.

They are NOT implementation specifications.

They do NOT override the current architecture or implementation.

---

## Authoritative Documents

The following documents remain the sole implementation authority:

- CLAUDE.md
- SD-001
- DS-001
- PE-001
- IMP-001

If any historical concept conflicts with these documents, the
authoritative documents always take precedence.

---

## How Historical Concepts Shall Be Used

Before implementing or refining any Workspace or Enterprise Experience:

1. Review the relevant historical concepts.
2. Map each concept to the current Workspace and Capability.
3. Classify every concept as:
   - KEEP
   - EVOLVE
   - RETIRE
4. Extract reusable interaction patterns and design principles.
5. Do NOT replace existing implementation unless there is a demonstrable
   Enterprise Experience improvement.

---

## Implementation Rules

Historical concepts may be used only to extract:

- interaction patterns
- information hierarchy
- navigation concepts
- cognitive workflows
- executive communication
- progressive disclosure
- evidence presentation
- visual inspiration

Do NOT copy HTML.

Do NOT copy layouts verbatim.

Do NOT recreate outdated navigation models.

---

## Repository Principle

Historical concepts preserve product vision.

The production implementation realizes that vision using the current
AUREX architecture.

Architecture governs implementation.


Historical concepts inform design.
