## BA-01 — Understand Evidence Context

### Business Activity Contract (IMP-001 §6.7)

- **Business Intent:** Retrieve the current governed state of an Evidence record — by identity, or by a filtered `linked_entity_type`/`linked_entity_id`/`evidence_source`/`evidence_type` criterion — without establishing, mutating, or altering any object returned. Realizes `SD-002-040`'s "first-class... governed object" framing for the read side, operationalizes `SD-002-044`'s "reusable across objects" principle by making that reuse queryable for the first time.
- **Input Contract:**
  - Single-item branch: `evidence_id` (UUID, path parameter).
  - List branch: `linked_entity_type`, `linked_entity_id`, `evidence_source`, `evidence_type` (all independently optional query parameters). Omitting all four returns every Evidence row visible to the caller.
- **Output Contract:** Single-item branch returns one `EvidenceResponse` (404 if the id does not exist, or exists but belongs to a different Organization and the caller is not `PLATFORM_ADMIN` — anti-enumeration, never a disclosing 403). List branch returns `EvidenceListResponse` (possibly empty; never an error for zero matches).
- **Business Rules:** Read-only in both branches — no `evidence_registry` row is created, mutated, transitioned, or deleted by either endpoint. `EvidenceRegistryRepository.create()`/`create_linked()` (WP-11 BA-03 / WP-14 BA-05) are untouched.
- **Validation Rules:** None beyond standard path/query-parameter type coercion (a malformed UUID is rejected with 422 by FastAPI/Pydantic before either handler is reached).
- **Authorization Rules:** `RO-DEC-C066-BA01-03` (Option C) — `dependencies.get_current_claims` (authentication only); Organization-scoping performed inside the repository query (exact-match `organization_id` predicate, never `OR organization_id IS NULL`, since `evidence_registry.organization_id` is `NOT NULL`). No `PLATFORM_ADMIN` requirement for ordinary same-Organization reads. `PLATFORM_ADMIN` additionally retains cross-Organization read access on the single-item branch only (`TDS-015 §9`/§13); the list branch never returns cross-Organization rows for any caller, including `PLATFORM_ADMIN` (`RO-DEC-C066-BA01-05`).
- **Idempotency:** Both endpoints are naturally idempotent — pure reads with no side effect.
- **AI Assistance:** None implemented — `SD-002-050` reserves Evidence governance actions to humans; a read-only Business Activity touches none of them.
- **Domain Events:** None published — a read has nothing to announce.
- **Audit Requirements:** None recorded — a read produces no state change for `SD-002-054`'s seven audit questions to describe, correctly cited to `IMP-REPORT-WP-06` line 26 / `CERT-WP-06` (not `IRA-006`, which never discusses audit requirements — `TDS-015`'s own independently-verified citation correction).
- **Tests:** `Backend/Services/AIService/tests/test_evidence_api.py` — 17 new tests. See Validation below.
